# 遊戲設計文件：從產地到餐桌（暫名）

## 目標與受眾

給**完全不了解合作社**的一般民眾玩的線上小遊戲，透過角色扮演與抉擇，體會「生產者 + 消費者」共同組成團結經濟合作社的過程：為什麼要合作、合作社如何運作、治理民主怎麼落實、合作社通常怎麼失敗。

內容改編自簡報《從產地到餐桌：如何經濟民主》（洪敬舒），所有情境與案例皆為**改寫詮釋**，非逐字引用。

## 核心玩法

單人、回合制的文字抉擇模擬遊戲（decision-based sim）。玩家扮演合作社的發起人之一，在三個發展階段中，面對一系列取材自簡報概念的情境事件，做出選擇。每個選擇會影響五項指標，指標會左右能否進入下一階段，以及最終結局。

### 五項核心指標（0–100，初始 50）

| 指標 | 對應簡報概念 |
|---|---|
| 信任 Trust | 相互信任、交換與信任理論、社會連帶 |
| 民主參與 Democracy | 民主控制、Laidlaw 民主健檢原則 |
| 生產者關係 Producer Relations | 生產者困境、反抗通路剝削 |
| 消費者滿意度 Consumer Satisfaction | 消費者困境、糧食主權 |
| 財務 Finance | 共同採購/銷售/信貸的規模經濟 |

任一核心指標（信任、民主、財務）歸零 → 立即觸發失敗結局，並對應簡報「合作社為何失敗」的四大類原因之一：
- **誤解合作**（過度浪漫／過早啟動）
- **支持不足**（成員參與不足／財務支持不足）
- **權力集中**（能力集中／利潤集中／所托非人）
- **治理失敗**（理監事固定化／價值未傳承／缺乏調解機制）

### 三個發展階段（對應簡報「農業合作的三階段發展」）

1. **共同採購**：降低投入成本，建立初期互信。核心張力：搭便車效應、旁觀者效應、木桶理論（最弱一環）。
2. **共同銷售／品牌**：繞過中間商，直接建立產地到餐桌通路。核心張力：權力集中、治理透明、重大決策是否交付社員表決（Migros 公投事件為原型）。
3. **共同信貸／加工整合**：規模化、垂直整合（Ocean Spray 案例為原型）。核心張力：擴張風險、世代傳承、治理固定化。

每階段包含 4 個情境事件 + 1 個「民主健檢」小測驗（改編自 Alexander Laidlaw 的民主原則檢核）。

### 結局分歧（存活過三階段後，依最終指標組合判定）

- **深耕社區型**：生產者關係與消費者滿意度皆高，呼應「社區不是一種業務」的理念。
- **垂直整合型**：財務與規模皆高，呼應 Ocean Spray 從初級農產品到品牌加工的路徑。
- **穩健民主型**：信任與民主參與均衡，規模普通但治理健全。
- **勉強維持型**：指標皆未歸零但普遍偏低，鼓勵玩家重玩、嘗試不同選擇。

### 合作社小百科（Glossary）

選擇特定選項後會解鎖百科條目（改寫自簡報案例），例如：比利時 Bees Coop、巴黎 La Louve、北美消費合作社案例、愛爾蘭社區合作社、Migros 公投、Ocean Spray 三階段整合、雁行理論、交換關係矩陣、合作的公式（共同承諾＋共同利益＋相互信任）、國際合作社七大原則。玩家可隨時在遊戲中打開百科查閱，遊戲結束畫面會列出本局解鎖的條目數。

## 技術架構

- **零建置、純前端**：`index.html` + `css/style.css` + 一般 `<script>` 標籤載入的 `js/*.js`（無 ES module、無 bundler），確保雙擊 `index.html` 或任何靜態伺服器（含 GitHub Pages）都能直接執行，不需要 Node.js 環境。
- `js/content.js`：三階段事件資料（情境、選項、指標增減、回饋文字、解鎖的百科條目 id）。
- `js/glossary.js`：百科條目資料。
- `js/state.js`：遊戲狀態物件與指標運算（clamp、失敗判定、結局判定）。
- `js/ui.js`：畫面渲染（事件卡、指標條、百科彈窗、結局畫面）。
- `js/main.js`：遊戲流程控制與事件綁定，程式進入點。
