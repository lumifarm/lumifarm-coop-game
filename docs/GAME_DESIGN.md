# 遊戲設計文件：食農新日常——從產地到餐桌的農業經濟民主之路

## 目標與受眾

給**完全不了解合作社**的一般民眾玩的線上小遊戲，透過角色扮演與抉擇，體會「生產者 + 消費者」共同組成團結經濟合作社的過程：怎麼找到第一批夥伴、為什麼要合作、合作社如何運作、治理民主怎麼落實、合作社通常怎麼失敗。

內容改編自簡報《從產地到餐桌：如何經濟民主》（洪敬舒），所有情境與案例皆為**改寫詮釋**，非逐字引用；合作社小百科的每一則條目也都在遊戲內標註了這個共同的資料來源。

## 核心玩法

單人、回合制的文字抉擇模擬遊戲（decision-based sim）。玩家扮演「光農合作社」的發起人之一，在四個發展階段中，面對一系列取材自簡報概念的情境事件，每個事件有**四個選項**（增加彼此的鑑別度，避免落入單純的「好/中/壞」三選一），做出選擇。每個選擇會影響五項指標，指標會左右能否進入下一階段，以及最終結局。

### 五項核心指標（0–100，初始 50）

指標旁即時顯示五級評語（危急／警訊／普通／良好／優秀），每次選擇後也會以浮動徽章＋脈動效果呈現增減量。

| 指標 | 對應簡報概念 |
|---|---|
| 信任 Trust | 相互信任、交換與信任理論、社會連帶 |
| 民主參與 Democracy | 民主控制、Laidlaw 民主健檢原則 |
| 生產者關係 Producer Relations | 生產者困境、反抗通路剝削 |
| 消費者滿意度 Consumer Satisfaction | 消費者困境、糧食主權 |
| 財務 Finance | 共同採購/銷售/信貸的規模經濟 |

任一核心指標（信任、民主、財務）歸零 → 立即觸發失敗結局，並對應簡報「合作社為何失敗」的四大類原因之一：
- **誤解合作**（過度浪漫／過早啟動）
- **支持不足**（成員參與不足／財務支持不足）
- **權力集中**（能力集中／利潤集中／所托非人）
- **治理失敗**（理監事固定化／價值未傳承／缺乏調解機制）

### 四個發展階段

0. **結識夥伴**：正式成立之前的宣傳、招募與磨合——怎麼找到第一批小農與消費者、怎麼談出第一份契作默契、要不要現在就正式登記。呼應簡報「有共同需求就能合作嗎」的提問（為什麼需要合作社／誰需要／屬於誰／服務誰）。
1. **共同採購**：降低投入成本，建立初期互信。核心張力：搭便車效應、旁觀者效應、木桶理論（最弱一環）。
2. **共同銷售／品牌**：繞過中間商，直接建立產地到餐桌通路。核心張力：權力集中、治理透明、重大決策是否交付社員表決（Migros 公投事件為原型）。
3. **共同信貸／加工整合**：規模化、垂直整合（Ocean Spray 案例為原型）。核心張力：擴張風險、世代傳承、治理固定化。

每階段包含 4 個情境事件（各 4 個選項）+ 1 個「民主健檢」小測驗（4 個選項，改編自 Alexander Laidlaw 的民主原則檢核）。

### 結局分歧（走完四個階段後，依最終指標組合判定）

- **深耕社區型** 🌱：生產者關係與消費者滿意度皆高，呼應「社區不是一種業務」的理念。
- **垂直整合型** 🏭：財務與規模皆高，呼應 Ocean Spray 從初級農產品到品牌加工的路徑。
- **穩健民主型** ⚖️：信任與民主參與均衡，規模普通但治理健全。
- **勉強維持型** 🌤️：指標皆未歸零但普遍偏低，鼓勵玩家重玩、嘗試不同選擇。

### 合作社小百科（Glossary）

選擇特定選項後會在回饋卡片中以**可點擊的超連結**列出剛解鎖的條目，點擊會直接開啟百科彈窗並捲動、高亮到該條目。條目涵蓋比利時 Bees Coop、巴黎 La Louve、北美消費合作社案例、愛爾蘭社區合作社、Migros 公投、Ocean Spray 三階段整合、雁行理論、Laidlaw 民主健檢、合作的三種理由、合作社基本原型、農業合作的三階段發展、全球合作社規模、個體戶小農的困境、距離與信任、北歐合作外溢效應、合作社與社區經濟等共 22 則，每則都標註「資料來源：改寫自簡報《從產地到餐桌：如何經濟民主》（洪敬舒）」。玩家可隨時在遊戲中打開百科查閱，遊戲結束畫面會列出本局解鎖的條目數。

## 視覺風格

以「食農新日常」為主軸的暖色系（大地綠＋赭橘）風格：
- 標頭有一枚原創的手繪風 SVG 徽章（麥穗＋合掌弧線，象徵農產與合作），favicon 使用 🌾。
- 頁面背景鋪有極淡的麥穗線稿重複紋樣（低對比度，不干擾閱讀）。
- 每個階段有專屬 emoji 圖示（🤝 結識夥伴／🧺 共同採購／🏷️ 共同銷售與品牌／🏭 共同信貸與加工整合），顯示於進度列與該階段的開場／小結卡片。
- 每種結局也有專屬 emoji 圖示，強化情緒收尾。

## 技術架構

- **零建置、純前端**：`index.html` + `css/style.css` + 一般 `<script>` 標籤載入的 `js/*.js`（無 ES module、無 bundler），確保雙擊 `index.html` 或任何靜態伺服器（含 GitHub Pages）都能直接執行，不需要 Node.js 環境。
- `js/content.js`：四階段事件資料（情境、選項、指標增減、回饋文字、解鎖的百科條目 id、階段圖示）。
- `js/glossary.js`：百科條目資料，統一附帶 `source` 欄位。
- `js/state.js`：遊戲狀態物件與指標運算（clamp、五級評語、失敗判定、結局判定與圖示）。
- `js/ui.js`：畫面渲染（事件卡、指標條與動態徽章、百科彈窗、教學彈窗、回饋表單、結局畫面）。
- `js/main.js`：遊戲流程控制與事件綁定，包含教學彈窗的顯示/略過邏輯（`localStorage`）與意見回饋的 Email／GitHub Issue 送出邏輯，程式進入點。
